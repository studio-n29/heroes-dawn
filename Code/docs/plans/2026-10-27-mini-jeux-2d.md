# Lot H : les 9 mini-jeux 2D, plan d'implantation

> **Pour l'exécutant :** utiliser superpowers:executing-plans (exécution native). Les étapes se cochent avec `- [ ]`.

**Objectif :** rendre jouables au test public les 9 mini-jeux du PDF N29 HQ dans les 4 zones de Brooklyn : 7 nouveaux jeux 2D, la survie en neige refaite en 2D, le dialogue inchangé.

**Architecture :** chaque jeu est une classe de domaine pure et déterministe (`Domain/Board/Activities/Games`), exposée par un type d'activité enregistré dans `ActivityRegistry`. Une fenêtre commune `Popups/MiniGame2DPopup` fait tourner un « pilote » (`IMiniGameDriver`) par jeu, qui dessine dans la zone de jeu et relaie les entrées. `CasePopupPresenter` ouvre cette fenêtre pour les nouveaux types.

**Technologies :** Unity 6000.6.3f1, C# nullable, NUnit, VContainer, UniTask, uGUI, recettes de prefab `IPrefabRecipe`. Les dossiers ci-dessous sont relatifs à `Code/Heroes Dawn Unity/`.

**Spec :** `Code/docs/specs/2026-10-27-mini-jeux-2d-design.md`.

## Contraintes globales

- Textes visibles, tests et docs en français ; commentaires de code en français ; commits terminés par `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` ; ni push ni merge ; ne jamais ajouter `03_Art_UI_UX/Prompts_a_coller_C2.md` à un commit.
- Fins de ligne : beaucoup de fichiers sont en CRLF. Modifier par l'outil Edit ou par un script Node qui normalise les fins de ligne (scripts dans le dossier scratchpad de la session, jamais `node -e` avec apostrophes).
- Les classes de jeu vivent dans `Packages/com.n29.heroesdawn.domain/Domain/Board/Activities/Games/`, namespace `N29.HeroesDawn.Domain.Activities.Games`, sans référence à Unity. Hasard : `new Pcg32(seed).Fork(n)` (interface `IRandom` : `Range(min, maxExclusive)`, `Chance(percent)`). Ne jamais utiliser `System.Random` ni l'horloge.
- Chaque jeu a un constructeur `(ulong seed, ActivityParameters p)` et lit ses réglages par `p.Get("clé")`. Les bornes sont celles du `ParameterDef` du type (déjà appliquées par `ActivityRegistry.Resolve`).
- Tous les jeux exposent la même forme : `Status` (`GameStatus`), `Score`, `Target`, `TimeLeft` (−1 s'il n'y a pas de minuteur), `Lives` (−1 s'il n'y a pas de vies), `Step(float dt)`, `Abandon()`, `Result()` (via l'interface `IMiniGame`).
- Cibles tactiles ≥ 96 px pour les boutons (test `HubLayoutTests`) ; les cibles de jeu (nœuds, caisses, pistes) sont plus grandes que leur dessin.
- Tests Unity en lot, éditeur fermé, par le script `ut.sh` de l'espace de travail (`bash <espace>/ut.sh EditMode|PlayMode "<filtre>"`). Prefabs régénérés par `PrefabGenerator.GenerateAllBatch -overwrite <chemins>`.
- Une fenêtre de mini-jeu ne doit jamais bloquer l'écran : réussite, échec, abandon, Retour matériel et annulation rendent toujours un `ActivityResult`.

## Revue ciblée (Review Focus)

1. Une partie qui se termine, est abandonnée ou annulée (Retour, destruction de la page) rend toujours la main : pas d'écran bloqué.
2. Chaque niveau généré est jouable jusqu'à la victoire (engrenages, ingénierie, ADN, infiltration, tir franc) quelle que soit la graine, avec les réglages min et max.
3. Les 9 jeux sont réellement placés dans les 4 zones et chaque case se résout (gains versés, case marquée terminée) en réussite comme en échec ; un échec ne crée pas de boucle infinie.
4. Un appui répété (double tap sur Commencer, Abandonner pendant la fin de partie) ne lance ni deux parties ni deux résultats.
5. Le joystick virtuel et les entrées maintenir/relâcher ne gardent pas d'état d'une partie à l'autre (relâchement perdu, doigt qui sort de la zone).
